Second build · second-island

The instruments came before the island.

The second build started clean on 18 August 2026. Before it drew anything, it built the tools that would judge it, then proved each tool by breaking a copy of the build and watching the tool notice. This page explains what that means, and what is on screen today.

Stage 0

Every checker was watched failing before it was trusted.

A digital twin is a working model of a real place that runs on a computer and can say where each of its numbers came from. The second twin of Minjerribah is called second-island, and it opened with one rule: nothing else starts until every instrument has caught a fault that was put there on purpose.

An instrument, in this build, is a checking program: a script that runs over the build and reports what it finds. A fault is a deliberate break, switched on by name. One fault makes a system read the real clock. Another makes a panel lose its label. Another moves one departure time in the timetable by five minutes.

The self-test runs every instrument twice for every fault: once on a healthy copy of the build and once on a copy with the fault switched on. A result counts as caught only when the instrument passed on the healthy copy, failed on the broken copy, and its failure named what the fault registry says it must name. An instrument that crashed for some other reason is not counted as having seen anything.

The result is written into a file the build calls the jurisdiction matrix: which instrument owns which claim, and which faults nothing catches. One blind spot is named there with its reason: a mobile number sitting in the sealed download inbox, which the personal-data rule does not scan. The build's own words for the standard it holds itself to, from its Stage 0 document: "'Exists, untested' is an acceptable row. 'Works' without a receipt is not."

Instrument

Headless

Runs the whole simulation in a terminal with no browser and no picture. Fails loudly if a system throws an error or runs over its time budget.

Instrument

Determinism

Runs the world twice from one seed and compares. On a difference it names the first tick that differed and the system that drifted.

Instrument

Shot

Checks a picture of the calibration scene pixel by pixel against sample points with expected colours. It is required to miss a renamed label, which proves on the record that a screenshot cannot see the interface.

Instrument

Bench

Times the frames and reports the slow end and the single worst frame, against a budget. The average is not reported, because reporting it invites someone to quote it.

Instrument

Interface probe

Every panel has a name, every number on screen points at a record on disk, and an unknown value shows the marker and no number.

Instrument

Gate

Runs fourteen rule modules over the files and blocks the build on a broken rule. The rules are listed further down this page.

Instrument

Board

The build's noticeboard, one note per file. A finding that lives only in a chat is treated as never made, so findings go here before a session ends.

Instrument

Selftest

The instrument that checks the instruments. It injects every fault, runs every column, and writes the jurisdiction matrix.

The kernel

One tick is one island minute.

The kernel is the small core every other part runs on: the clock, the store that holds facts, the shape a fact must take, and the streams of random numbers. Four things about it decide how the rest of the build behaves.

  • Whole ticks, one per minute. The island advances in whole steps and one step is one island minute, 1,440 a day. Timetables are published in minutes, so no conversion happens anywhere.
  • No wall clock. A wall clock is your computer's own time. Nothing under the simulation reads it. The island's clock is its own, and a gate rule scans the code for any call to the real clock.
  • No unseeded randomness. A seed is a starting number that a random-number generator grows from. Every random number in the build comes from a named stream derived from one seed, so adding a new system does not shift another system's numbers.
  • The part that computes does not touch the part that draws. A gate rule checks the imports. This is what lets the whole island run in a terminal, which is what makes the next property testable at all.

Together these make the build deterministic: the same starting point gives the same result every time. The same seed gives the same island on anyone's machine. When two runs differ, the determinism instrument names the first tick that moved and the system that moved it. The first build could report that two runs differed and not which system had moved.

Headless means the simulation runs with no picture at all. The README records a simulated year running in a terminal in 0.144 seconds on the machine that measured it, about the length of a blink.

The record

Every fact carries eight fields.

A record is one fact the twin holds: a departure time, a jetty, a bus call, a tide reading. Provenance is where a fact came from and when it was believed. In this build a record cannot be stored bare. The kernel refuses any record that does not carry all eight of these fields, and a gate rule checks every data file for them.

FieldWhat it holds
sourceAn id in the build's list of sources, not free text. A record may not name a source that is not in the list.
locatorThe page, column, section or web address fragment: enough to check the claim in one step.
valid fromWhen this became true of the island.
valid toWhen it stopped being true. Empty means still true.
recorded atWhen the twin learned it.
recorded untilWhen the twin replaced it with a newer belief. Empty means this is the current belief.
confidenceHow sure: high, medium, low, contested or unknown.
registerWhich kind of claim it is: known, modelled, proposed or contributed.

Two of the pairs are times, and they are different times. "Valid" is the island's time: when the thing was so. "Recorded" is the twin's time: when the twin believed it. Both are kept because a decision made on a Tuesday from a figure that was corrected on the Thursday can only be judged fairly by asking what Tuesday could see. A store that overwrites on correction can no longer answer that.

A correction

What happens if SeaLink publishes a new time

The old record is not edited. It is given a "recorded until" date, which closes that belief, and it keeps its window. A new record is added with the new time and its own "recorded at". Both stay in the store, so the twin can still say what it believed before the change. A fault named correction-overwrites, which makes a correction replace the old belief instead, is in the registry, and the two-time store was watched catching it.

The departure times the owner supplied on 19 August 2026 also carry a seal: a second copy of every time, vessel code and day rule, held by a gate rule. A changed time blocks the build until the pack, the transcription and the seal are changed together and the board records who read the new timetable and when. That is the intended cost.

The source ladder

Four rungs, and a dated "not known" is an answer.

When a panel asks for a value, the build does not take the first figure it finds. It resolves the question through a ladder of sources, best first, one ladder per field.

  1. Island instrument. A sensor on this island, reporting itself.
  2. Official observation. A reading from a body that publishes it.
  3. Model. A published model or forecast for this place.
  4. Simulation. What this twin computed. The bottom rung.

Two rules make it an instrument rather than a preference. First, freshness demotes: a reading older than the window declared for its field drops one rung, so a stale official observation ranks where a model would, and a stale simulation falls off the ladder. The window is declared per field, because the useful age of a tide reading and of a bus timetable are not the same number. Second, in the build's own words from the ladder file: "The bottom rung never wins in live mode." If the only thing that could answer a live question is the twin's own simulation, the answer is "not known", with the date.

The ladder returns one of two shapes: a value with its rung, its source and its date, or "not known" with the date it was asked and the reason. Two shapes on purpose, so a panel cannot print "not known" as a number.

The tide is the standing example. Harmonic constituents are the set of numbers that describe how the tide at a port rises and falls. No published table for the Dunwich standard port has been obtained, so the tide pack ships zero constituents and the tide panel reads "contested or unknown" with the date, rather than a number. A value whose confidence sits below the bar shows that marker and no number.

The gate

Fourteen rules, and a rule outside the gate does not exist.

The gate is a program that reads the files in the repository and reports a finding wherever a rule is broken. A blocking finding stops the build; an advisory one is printed and the build goes on. The contract states the principle in one line: "A rule that is not in the gate does not exist." Every rule in that document is either a check in the gate or carries the words NOT YET CHECKED and a reason.

  1. imports. The simulation does not import the renderer or the interface, directly or through a helper.
  2. no-wallclock. No wall clock and no unseeded randomness under the kernel, the systems or the world.
  3. lore. The cultural boundary. No Aboriginal language word appears unless it is on the allowlist, no word is coined, and no open question is described as approved. Cultural material does not enter the build.
  4. provenance. Every record in the data carries its source, its locator and the two times.
  5. style. No em dash, no en dash between words, Australian spelling.
  6. personal. No personal contact detail under the data, the assets or the documents.
  7. sealed. The staging trees, where raw downloads land, are sealed against being committed, proven by asking git.
  8. derived. Nothing derived from a download is committed while its licence question is open, and every derived record carries the eight fields.
  9. crossings. Passenger and vehicle crossings stay apart: no sum of the two, no field that could hold both, no count written without its service or its landing point.
  10. ground-truth. The timetable in the pack is the one the owner supplied: every departure time, vessel code and day rule still matches, and the structure matches its seal.
  11. ports. The first build's two server ports are not bound or written here, so the two builds cannot collide on one machine.
  12. board. Every note on the noticeboard has the front matter the board tool and the reader rely on.
  13. instruments. The fault registry and the source agree: no undeclared fault hook, no unproven instrument, no unexplained blind spot.
  14. failure-modes. Advisory by design. A claim that something cannot work needs a measurement near it, or a record that the question was put to someone who would know.

Run on 20 August 2026 after the front page was split from the lab, the gate reported "PASS: 0 blocking, 15 advisory", the advisories all pre-existing.

The lab

The bench has its own page.

The lab is the instrument bench: the calibration scene, the island clock, the sun and tide panels, and the controls that step time forward. A calibration scene is a fixed picture with known colours at known points, so a program can check what the renderer drew, pixel by pixel. It carries no island data on purpose. As the page itself says: "Flat rectangles on purpose." Geometry drawn from island data could not be checked this way, because then the test would be testing the data.

The pale plate under the squares holds a swatch whose colour changes with the tick. Two frames taken at different ticks must differ there, which is how the shot instrument tells a live renderer from a frozen one.

The interface is checked by two witnesses, because a picture of a page cannot contain the page's labels. The page walks its own structure and posts a report of every panel and value. Separately, an accessibility tree, the list of named parts a screen reader would see, is read from the outside and compared to that report. On 20 August 2026 the shot check passed 6 of 6 sample points, and the probe of the front page passed 10 rules over 8 panels and 28 values, at two different minutes.

Until 20 August 2026 the bench was the front page. It was split so that a person arriving meets the ferry question and not a calibration target. The bench moved to lab.html and every instrument was pointed at the page its target now lives on.

What the page shows is what the instruments have proven

  • The calibration scene and the island clock.

Not there

What the README says is not built

  • No island geometry. No terrain, no buildings, no map. The README's words: "There is no island yet." A terrain would come from the elevation lane, which has not been run.
  • No residents. None have been generated. When they are, each would be disclosed as generated on every card, a rule the contract lists as not yet checked because no people exist.
  • No live feed. The ferry page is the printed timetable read against the island clock, and no boat is tracked. A live rung would sit above the timetable on the ladder; nothing feeds it.
  • Downloads waiting. Five connectors have fetched real data with receipts: OpenStreetMap, TransLink, past weather, the 2021 census and the Atlas of Living Australia. Only the bus pack is committed. The rest sits in a sealed inbox until the licence question is decided.
